# Pin Electronics：ATE 业务关系与联动逻辑

日期：2026-11-23  
适用页面：`/pin-electronics`  
文档性质：业务规则与后续实现依据。本次仅整理文档，不修改业务代码。

## 1. 业务目标与适用边界

Pin Electronics 是 ATE（自动测试设备）中连接测试资源与 DUT（被测器件）引脚的配置入口。用户在这里决定：测试哪个引脚、何时驱动或比较、施加什么电平、使用什么负载，以及是否切换到参数测量资源。

正确的联动应遵循以下顺序：

> 确定配置对象 → 读取该对象的配置 → 修改指定参数 → 更新派生显示与校验 → 提交配置 → 在接入硬件时确认实际生效状态。

本文件区分三类规则：

| 标记 | 含义 |
| --- | --- |
| 通用关系 | ATE 中通常成立的业务区分，例如驱动电平和比较门限属于不同用途 |
| 本项目建议 | 为本页面建议采用的明确交互和数据规则，尚未实现的内容不代表现有能力 |
| 设备相关 | 必须由具体板卡、测试机手册或 API 明确的规则，不能凭字段名称推定 |

当前没有提供 Pin Electronics 所属板卡的完整手册与通信协议。因此，本文可以确定参数之间的职责和联动边界，但不宣称某一组 D/R 编号、最小脉宽、量程或继电器顺序是所有 ATE 的统一标准。

## 2. 首先区分三种“刷新”

| 刷新类型 | 触发方式 | 应产生的结果 |
| --- | --- | --- |
| 配置与显示刷新 | 修改输入、切换 Pin/TimeSet、应用预设 | 读取或修改配置，更新控件、示意图和校验 |
| 硬件状态刷新 | 下发成功、查询设备、收到设备状态事件 | 更新实际模式、资源连接、已应用配置版本等 |
| 测量结果刷新 | 执行测量并收到结果 | 更新实测电压、电流、频率、计数或比较结果 |

三者不能相互代替：

- 浏览器保存成功，只说明本地配置被保存。
- 电路图显示继电器闭合，不足以证明真实继电器闭合。
- `Rate = 1 / Period` 是配置周期对应的速率，不能视为 Counter 实测值。
- 修改电平或时序后，旧测量结果应标为历史结果或已过期，不能自动变成新配置下的结果。

## 3. 业务对象与参数归属

### 3.1 配置上下文

建议将当前上下文理解为：

```text
测试程序 / 测试工程
├── Pin Map：逻辑引脚 → Site 对应的物理资源
├── Timing Set：周期与各引脚的时序配置
├── Level Set：各引脚的电平与负载配置
└── 仪器配置：驱动模式、资源连接、PPMU、Counter

当前查看对象
└── 当前 Pin（或明确的 Pin Group）
    + 当前 TimeSet
    + 当前 Level Set（如果系统只有一个，可隐含）
    + 当前 Site / 资源上下文（设备支持时）
```

Site 表示多工位测试中的 DUT 实例。当前页面没有 Site 和 Level Set 选择器，不要求立即新增；但数据归属不应因此把所有参数塞进一份全局对象。

### 3.2 参数归属表

| 对象 | 包含内容 | 切换或修改时的影响范围 |
| --- | --- | --- |
| Pin Map | Pin 名称、Pin Group、Site 到物理通道的映射 | 通道标识、资源能力、配置目标和测量目标 |
| TimeSet | TimeSet 身份、周期 Period | 共享该时序域的相关 Pin，及该 TimeSet 的 Rate |
| Pin × TimeSet | Drive Format、驱动边沿、比较选通时间，以及设备定义为时序局部的属性 | 当前 Pin 在该 TimeSet 中的时序行为 |
| Pin × Level Set | Vih/Vil、Voh/Vol、Vt、Ioh/Iol、钳位等配置（以设备支持项为准） | 引用该电平配置的测试上下文 |
| Pin / 资源的共享属性 | 如本项目 MIO16 已约定的 Compare Mode | 该 Pin 下所有引用此共享属性的 TimeSet |
| 仪器 / 资源连接状态 | Driver Mode、主连接、PPMU 连接、负载使能等 | 实际资源通路，不能仅按界面 TimeSet 分割 |
| PPMU 配置 | 强制模式、强制值、限制值、量程及测量配置 | 所选 Pin 对应的参数测量资源 |
| Counter 配置 | 输入资源、计数边沿、门控时间、设备定义的触发条件 | 当前计数测量任务 |
| 测量记录 | 结果、单位、状态、时间、Pin/Site 和配置版本 | 一次确定的测量或执行，不是可编辑配置 |

关键约束：

1. **Period 通常由同一 TimeSet / 时序域中的多个 Pin 共享。** 从当前 Pin 页面编辑周期，也可能影响其他 Pin，界面应说明影响范围。
2. **电平配置通常独立于 TimeSet。** 只有测试程序明确绑定了不同电平集时，切换测试上下文才应连带切换电平集。
3. **Compare Mode 的存储层级由设备决定。** 本项目 MIO16 需求文档已规定它按 Pin 跨 TimeSet 共享；若本页面复用该模型，应遵守此约定，而不是给每个 TimeSet 各存一份。
4. Init State、Start State、Disable Compare 的作用域和执行时机仍需设备定义。不能仅因它们放在 Format / Timing 区域，就认定全部属于 Pin × TimeSet。
5. `porta`、`portb` 等名字本身不能证明对象是单 Pin 还是 Pin Group。若代表组，必须显示成员和批量影响范围。

## 4. 上下文选择的联动

### 4.1 切换 Pin / Pin Group

本项目建议流程：

1. 保留原对象的草稿，草稿按对象身份隔离。
2. 根据 Pin Map 解析新对象的物理通道及能力。
3. 读取新 Pin 在当前 TimeSet 下的时序配置。
4. 读取新 Pin 在当前 Level Set 下的电平与负载配置。
5. 读取新资源的仪器配置、连接状态和对应测量记录。
6. 同步页面顶部与电路区的 Pin 选择，重新计算有效控件和校验结果。

**不能把原 Pin 的值直接改名成新 Pin 的配置。** 新 Pin 没有配置时，应明确显示未配置，或执行可见的初始化策略。

Pin Group 中成员值不一致时，应显示“多个值”或混合状态；用户修改某字段时，仅批量修改该字段，不能顺带覆盖成员的其他独立配置。

切换查看对象本身不应发送硬件切换命令，也不应主动断开原 Pin。

### 4.2 切换 TimeSet Name / TimeSet

当前页面同时存在名称和编号，但它们的业务关系尚未明确，后续应从以下模型中确定一种：

| 模型 | 正确行为 |
| --- | --- |
| 名称和编号是同一个 TimeSet 的两个标识 | 选择任意一个，另一个同步到同一记录 |
| 名称代表时序表，编号代表表内条目 | 修改名称后重新加载有效编号，再读取具体条目 |

不能允许名称与编号任意组合，却不验证组合对应的真实时序对象。

切换到有效 TimeSet 后，应刷新：

- 当前 TimeSet 的 Period 与 Rate。
- 当前 Pin 的 Drive Format、适用驱动边沿和比较选通时间。
- 各边沿的有效性、错误提示及格式预览（如提供）。

默认不随此操作改变：

- Pin 到物理通道的映射。
- 独立 Level Set 的电压、电流参数。
- 跨 TimeSet 共享的 Compare Mode。
- 实际继电器状态及已有硬件模式。

## 5. 时序区的联动

### 5.1 修改 Period

直接派生关系：

```text
Rate（MHz） = 1000 / Period（ns）
```

Rate 应标明是周期速率；DDR 等模式下的数据传输率以及具体信号的翻转频率，不能不加区分地沿用该数值。

修改 Period 后需要：

- 更新共享该 TimeSet / 时序域的相关页面显示。
- 重新校验所有受影响 Pin 的有效边沿，而非只校验正在查看的 Pin。
- 更新时间轴终点、刻度和预览范围（如提供）。
- 检查设备支持的周期范围、量化步长和时序限制。

本项目建议，绝对时间边沿保持原值；缩短周期导致越界时提示错误，不静默缩放或截断。若未来支持百分比或表达式边沿，如 `0.5 × Period`，才按其明确的定义重新计算。

单周期编辑模型通常检查有效边沿是否在周期范围内。是否允许等于周期终点、跨周期边沿或特殊偏移，由设备决定，不能统一硬编码为所有机型同一种边界。

示例：原周期 500 ns，R0 为 450.05 ns；改为 250 ns 后，Rate 变为 4 MHz，R0 保留并显示越界错误。在不支持跨周期的模型下，禁止将其作为有效执行配置提交。

### 5.2 修改 Drive Format

格式决定“何时更新数据、是否返回某种状态”，并进一步决定哪些驱动边沿有意义。

| 页面格式 | 通常表达的含义 | 必须确认的细节 |
| --- | --- | --- |
| NRZ | 在数据沿更新后保持，直到下一次有效更新 | 使用哪个 D 边沿、输出使能和跨周期保持规则 |
| RZ | 有效数据阶段后返回零状态 | 数据阶段、返回边沿、零状态定义 |
| RO | 若设备将其定义为 Return-to-One，则返回一状态 | 首先确认缩写定义，不能仅按名称推断 |
| SBC | 常见为以当前数据的互补状态包围有效数据阶段 | 所需边沿、周期边界和设备支持条件 |

联动要求：

1. 根据格式能力定义计算有效边沿集合。
2. 更新输入框可用性和格式说明。
3. 对新增的必需边沿检查是否已配置；需要默认值时明确告知。
4. 保留暂时无效的边沿草稿，但不将它们解释为当前格式的执行参数。
5. 更新预览与时序校验，不自动修改电压或物理继电器。

**D0、D1、D2、D3 不存在可直接套用到所有 ATE 的固定职责。** 本项目 MIO16 的专属规则不能未经确认直接搬到 Pin Electronics 的 NRZ/RZ/RO/SBC 模型。

实际驱动还取决于 Pattern 每周期的动作、数据和输出使能。只有格式、初态和边沿，通常只能绘制格式示意，不能声称已仿真真实执行波形。

### 5.3 修改 Compare Mode / Disable Compare

| 操作 | 应有联动 |
| --- | --- |
| 选择 Edge | 使用设备定义的离散采样时刻；当前项目若采用单采样点模型，则启用对应的一个 R 参数 |
| 选择 Window | 使用设备定义的窗口边界，校验先后关系与最小窗口宽度 |
| Disable Compare 开启 | 停止当前作用域的比较动作；保留门限、模式和边沿配置，更新有效性显示 |
| Disable Compare 关闭 | 按当前格式及模式重新计算有效比较配置，不无条件启用所有 R 边沿 |

Window 的窗口内判定方式必须由设备说明，例如整个窗口保持有效与窗口内事件检测不是同一种语义。

Disable Compare 不表示驱动关闭、引脚断开或有源负载关闭。Voh/Vol 可以继续作为未激活配置被编辑，也可以按界面策略暂时禁用编辑；无论哪一种，都不应自动清零。

对于共享 Compare Mode 的设备，修改它需要重新校验该 Pin 在所有相关 TimeSet 下的比较配置。

### 5.4 单边沿 Dis、Init State 与 Start State

边沿是否实际生效，至少受三类条件共同决定：格式支持、比较或驱动功能是否允许、用户是否禁用。应区分“用户主动禁用”和“当前格式不适用”，避免切换格式后丢失用户原选择。

格式必需的边沿不能被随意禁用；如果设备允许禁用，必须明确禁用后的波形语义。

Init State 与 Start State 应分别说明它们作用于初始化、启动 Pattern、周期边界或其他哪个阶段。修改静态配置不等于立刻施加电平；是否存在立即驱动操作，应单独定义。

## 6. 电平、比较门限与有源负载的联动

### 6.1 各参数的职责

| 参数 | 通常的业务含义 | 修改后应刷新 |
| --- | --- | --- |
| Vih / Vil | 测试机向 DUT 输入引脚施加的高 / 低驱动电平 | 对应驱动设定、幅度与量程校验；有电压预览时更新其刻度 |
| Voh / Vol | 测试机判定 DUT 输出高 / 低的比较门限 | 比较门限显示、门限顺序与输入范围校验 |
| Ioh / Iol | 对 DUT 高 / 低输出状态施加的有源负载电流 | 负载设定、量程及与被测输出能力有关的检查 |
| Vt | 常见为有源负载的换向参考电压 | 负载状态相关配置和设备约束检查；需核实该板卡定义 |
| Vch / Vcl | 从本页面命名和电路示意看，为高 / 低钳位设置 | 钳位范围及与目标电平的关系检查；实际通路需手册确认 |

同名符号在芯片数据手册与测试机界面中可能具有不同视角。例如 DUT 数据手册里的 VIH(min) 是输入高电平识别下限；测试机的 Vih 设置是实际施加的电压，两者有关联，但不能直接视为同一个数值。

### 6.2 合理的关联校验

普通双电平测试通常需要检查：

- 驱动高电平高于驱动低电平，比较高门限高于低门限；特殊测试模式按设备能力处理。
- 各设定值处于对应资源的量程、精度及允许组合内。
- 驱动电平、钳位和 DUT 允许电压相互兼容。
- 负载电流、输出电平以及 DUT 数据手册的规定测试条件相匹配。
- 电流正负号按统一的仪器方向约定解释；不得假设所有设备 Ioh 都必须为负、Iol 都必须为正。

这些是检查关系，不是自动赋值公式。修改 Vih 不应自动改写 Voh；修改 Ioh 也不能在没有器件模型或实测结果时计算出新的 Voh。

### 6.3 电平预设

应用预设属于用户明确触发的批量赋值：

1. 明确作用于哪个 Pin/Group 和 Level Set。
2. 明确包含哪些字段，只更新这些字段。
3. 按当前资源和 DUT 约束检查整组参数。
4. 更新相关显示并标记为待应用配置。

当前三个电平预设只覆盖七项电压，不覆盖 Ioh/Iol，也不调整时序。后续保持或扩展此范围，都应在预设定义中明确。

现有预设数值不能直接视为行业合规默认值。特别是 `LVTTL 5.0V` 的名称和参数需要复核：LVTTL 通常用于 3.3 V 逻辑描述，不能因此认定 DUT 可承受 5 V 驱动。预设应以 DUT 数据手册、测试目的和板卡能力为依据。

## 7. Driver Mode、继电器与 PPMU

### 7.1 模式和连接是不同维度

| 状态 | 业务含义 | 不能据此推断 |
| --- | --- | --- |
| Drive | 数字驱动功能被选择或允许 | DUT 此刻一定收到高电平，或主通路一定闭合 |
| HiZ | 数字驱动输出进入高阻状态 | DUT 与所有比较器、负载、钳位和测量资源完全隔离 |
| PPMU | 选择每引脚参数测量资源的相关工作方式 | PPMU 已连接、已开始施加或已经得到测量结果 |
| 继电器闭合 | 某条物理通路连接 | 通路上资源已正确配置，或允许与其他资源同时启用 |

电路图应按连接拓扑和有效资源状态决定哪些路径高亮。对于真实设备，建议同时区分请求状态与已确认状态。

### 7.2 数字驱动与 PPMU 的转换

正确业务目标是避免不允许的资源同时驱动同一节点。具体顺序必须由设备定义，软件应通过设备级转换流程执行，而不是让多个 UI 开关独立拼出任意组合。

该流程通常需要考虑：停止相关执行、释放冲突驱动、设置 PPMU 模式和限值、建立目标通路、等待规定的建立时间、再执行施加或测量；退出时也需要受控地撤销施加并恢复指定状态。

这里不规定“主继电器和 PPMU 继电器永远互斥”。有些拓扑可能需要组合连接，必须根据原理图和驱动接口制定允许状态表。

`Safe HiZ` 在当前代码中执行“数字模式设为 HiZ，两个布尔继电器状态设为断开”。接入设备后，是否覆盖有源负载、其他模拟通路和残余施加状态仍需确认，不能只凭按钮名称宣称全部电气隔离。

### 7.3 PPMU 模式与单位联动

| 强制模式 | Force Value | Compliance / Limit | 常见测量目标 |
| --- | --- | --- | --- |
| Force Voltage | V | 电流限制，A/mA/µA | 测量电流，如漏电 |
| Force Current | A/mA/µA | 电压限制，V | 测量电压，如连续性测试 |

切换强制模式时，需要同时更新字段含义、单位、量程、限制类型和测量通道。实际仪器也可能区分保护限值、钳位和量程，不能都只按一个通用 Compliance 字段处理。

**不能只替换单位，再把原数值原样解释成另一种物理量。** 建议分别保留各模式的配置；新模式无历史配置时，使用明确默认值或要求补全。

弹窗编辑先更新草稿，Cancel 放弃本次修改；Apply 校验后提交。是否连带切换硬件模式，必须从按钮含义中明确；若会切换，应按完整模式转换流程执行。

测量结果需包含成功、超量程、限值触发或错误等状态，不能只显示一个裸数字。

## 8. Counter 的联动

Counter 至少依赖输入资源、计数边沿和门控时间。是否复用数字比较器、采用哪个门限、是否存在专用输入路径，都属于设备相关信息。

| 修改内容 | 配置联动 | 结果联动 |
| --- | --- | --- |
| Pin / 输入资源 | 切换测量目标，检查资源可用性 | 显示该目标结果，不能沿用另一个 Pin 的结果 |
| Rising / Falling / Both | 修改计数规则 | 旧结果标记过期，下一次测量按新规则执行 |
| Gate Time | 修改观察窗口，可能影响更新耗时和计数分辨能力 | 重新测量后才更新结果 |
| 输入门限（若支持） | 修改有效边沿识别条件 | 旧结果标记过期 |

只有在信号和计数模式满足条件时，才可根据计数与门控时间推算频率。Both 统计的是双边沿事件，不能不考虑换算关系直接等同于信号周期频率；具体显示应由仪器测量模式决定。

## 9. 参数变化到显示变化的总表

| 用户操作 | 应更新的配置 / 派生显示 | 默认不自动改变 |
| --- | --- | --- |
| 选择 Pin | 通道、该 Pin 的时序和电平、仪器上下文、对应结果 | 其他 Pin 的配置、实际硬件输出 |
| 选择 TimeSet | 周期、Rate、当前 Pin 的时序及校验 | 独立电平集、物理映射、继电器 |
| 修改 Period | Rate、时间轴、共享该时序域的边沿校验 | 绝对时间边沿原值、电平 |
| 修改 Drive Format | 有效 D 边沿、格式预览、格式约束 | 电平、物理通路 |
| 修改 D / R | 对应位置、预览、相关约束 | 无关边沿和电平 |
| 修改 Compare Mode | 有效比较选通参数、窗口或采样显示、共享范围内校验 | 比较门限数值、驱动模式 |
| Disable Compare | 比较有效状态和执行配置 | 已保存门限、负载、驱动和连接 |
| 修改 Vih / Vil | 驱动设定及电气校验 | Voh/Vol、时序和测量值 |
| 修改 Voh / Vol | 比较门限及校验 | Vih/Vil、驱动波形 |
| 修改负载 / 钳位 | 相应电气配置与关联校验 | 无模型支持的 DUT 输出预测值 |
| 应用电平预设 | 预设明确包含的字段、整组校验 | 未包含字段 |
| 修改 Driver Mode / 连接 | 目标状态、拓扑校验、受控转换进度 | 未经设备确认的实际状态 |
| 修改 PPMU 模式 | 强制量、限值、量程、单位、该模式草稿 | 对不同物理量直接复用旧数值 |
| 修改 Counter 配置 | 测量配置、结果有效性 | 尚未测量的新结果 |
| Copy / Export | 导出的指定范围配置 | 当前配置、硬件状态 |
| Reset | 明确范围内的默认配置及校验 | 未说明范围的其他 Pin/TimeSet、即时硬件输出 |

## 10. 提交、生效与持久化规则

### 10.1 配置状态

建议区分：

```text
编辑草稿 → 校验通过 → 提交配置
                       ├── 离线：保存配置
                       └── 在线：设备接受 → 按接口能力确认生效
```

“本地已保存”和“设备已应用”应分别显示。若接口只有命令接受应答而没有回读能力，应说明确认能力，不能展示未经验证的实测状态。

多个相关参数的提交应校验整体一致性。设备无法原子应用时，应有明确的执行顺序和部分失败处理；发生超时或中途失败，不得把整组配置标为成功。

配置与测量结果应携带版本或等价关联信息，防止旧请求、旧测量返回后覆盖新 Pin、新配置的显示。

### 10.2 本地保存与重置

- 草稿按 Pin、TimeSet、Level Set 等真实归属分别保存；共享字段保存一份并被引用。
- 已保存配置优先于默认模板；修改默认值不会自动覆盖用户配置。
- 配置格式变化需要版本迁移，尤其涉及单位、作用域或字段物理含义变化时。
- Reset 应明确是当前 Pin 电平、当前 Pin 时序、整个 TimeSet，还是全部工程配置。
- 重置共享周期等参数时，应说明会影响其他 Pin。
- 在线环境中重置本地配置本身不应直接重新驱动 DUT，仍需遵循设备应用流程。

### 10.3 单位与能力约束

当前代码中 D0–D3 为 ps，R0/R1 和 Period 为 ns，Vil 为 mV，其他电压多为 V，负载电流为 µA。

业务计算前必须归一化单位。例如 `D1 = 50 ps` 等于 `0.05 ns`，不能与 `Period = 500 ns` 直接按裸数字比较。界面保留不同显示单位没有问题，但持久化、转换与校验必须有明确单位定义。

硬件分辨率、量程和允许组合应来自资源能力；输入框显示三位小数，不代表硬件支持该精度。量化或舍入后应显示设备实际可应用的值，不能静默改变测试条件。

## 11. 当前项目实现与目标规则的差距

| 当前代码事实 | 业务影响 | 后续方向 |
| --- | --- | --- |
| 所有字段在一份 settings 中 | 切换 Pin 只换名称和通道，其他值沿用 | 按真实作用域拆分配置和草稿 |
| TimeSet 名称和编号为独立枚举 | 无法保证对应同一有效时序对象 | 建立时序对象及标识关系 |
| Period 仅派生 Rate | 越界边沿没有关联校验 | 校验整个共享时序域 |
| Format / Compare Mode 仅保存枚举 | 有效边沿不随格式变化 | 引入经确认的格式能力定义 |
| 校验主要是单字段范围 | 不检查时序、电气与资源组合 | 分层增加关联校验 |
| 继电器、Driver Mode 可分别修改 | 没有设备允许状态与转换流程 | 按拓扑定义合法组合和受控转换 |
| PPMU 模式共用一个 Force Value 和 Compliance | 切换模式会沿用不同物理量的裸数值 | 分模式保存并按能力校验 |
| Counter 读数为占位符 | 不具备真实测量更新链路 | 接入采集接口后单独管理测量状态 |
| 两个时序页面与本页没有共享配置 | 同名业务值不会自动跨页面同步 | 先统一对象身份和语义，再共享数据 |
| localStorage 保存整份对象 | 默认值变化可能被缓存覆盖 | 增加明确版本、范围和迁移策略 |

路由实际加载 `file-transfer-web/src/views/PinElectronicsView/index.vue`；根目录的 `pin-electronics/` 是独立参考素材，修改它不会改变此路由的 Vue 页面。

## 12. 可验收的业务场景

| 编号 | 前置条件与操作 | 预期结果 |
| --- | --- | --- |

| A09 | 对混合值 Pin Group 修改 Vil | 只更新所有目标成员的 Vil，其他成员属性保留 |
| A10 | PPMU Voltage → Current | 单位、限制类型和量程变化，不把旧电压数值直接当作电流 |
| A11 | PPMU 草稿修改后 Cancel | 已提交配置与设备状态不变 |
| A12 | 在线执行模式转换时设备拒绝 | 显示失败或实际可确认状态，不把目标状态当作已生效 |
| A13 | Counter 修改门控时间 | 旧结果标记过期，新结果在重新采集后出现 |
| A14 | 旧 Pin 的测量结果在切换 Pin 后返回 | 归档到旧 Pin，不覆盖新 Pin 的显示 |
| A15 | 浏览器刷新 | 按配置版本恢复正确对象的数据；不自动重放危险或未确认的硬件动作 |
| A16 | 检查 D1=50 ps 与 Period=1 ns | 按 0.05 ns 校验，不误判为 50 ns |
