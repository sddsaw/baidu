### P1：2XCLK 的 Pattern 取位粒度错误

位置：`src/views/Mio16TimingView/model.ts:87–99`。

截图 `8.png`、`9.png` 的 pattern=1 表示一个 tester cycle 输出 A/B 双脉冲；pattern=0 表示该周期保持高/低。只有 `DDR_NR`（7.png）明确每半周期消费独立数据。当前代码对三类 DDR 一律使用 `(cycle * count + h)`，使 2XCLK 每半周期消费一位。

复现：Period=100、2XCLK_POS/NEG、Pattern=10、Periods=2。当前 D1 事件出现在 12.5 ns 和 112.5 ns（两个周期都是 A 脉冲），应为 12.5 ns 和 62.5 ns（第一个周期 A/B 两脉冲，第二周期保持）。浏览器也观察到只有 D1 A、没有 D1 B，B 被加入额外边界电平改变。

建议：分别定义 tester cycle 的重复次数与 Pattern 消费次数；2XCLK 每 tester cycle 消费一位，A/B 共同使用，DDR_NR 才按半周期消费。补充 10、01 跨周期回归用例。现有脚本只对时钟测试全 1/全 0，掩盖了该错误。

### P2：有效 D0 没有出现在五种格式的预览中

位置：`src/views/Mio16TimingView/components/TimingLane.vue:45–49`、`model.ts:94–104`。

D0 是 NR/RH/RL/RC/DDR_NR 的有效 Drive On，定义截图及原 Timeset Basic 均保留其位置。当前 driveLabels 仅取自电平变化事件；这些格式的事件流没有 D0，NR 格式示意更直接只返回 D1。

复现：默认 DIO00.NR 的 D0 从 10 改为 20（仍满足 D0≤D1），波形路径不变、标签仍只有 D1，两种显示模式都无法核对驱动开启时间。DDR_NR 同样看不到 D0 A/B。

建议：将边沿位置标记与电平变化事件分开生成；补上 D0 标签/短刻度，不需要恢复用户先前要求去掉的无关虚线，也不应让 NR 在 D0 新增交叉。

### P2：同为 DDR 的格式切换覆盖 B 行数据

位置：`src/views/Mio16TimingView/model.ts:43`。

只要从 DDR_NR 切到 2XCLK，或反向切换，isClock 改变就调用 defaultEdges 重建整个 B 行。两者的半周期时间范围相同，除了共享 D0 等约束，D1 无须重置。此行为并非截图要求，页面仅提示 SDR/DDR 切换初始化。

复现：DDR_NR 的 B.D1=70，切到 2XCLK_POS 后无提示变为 62.5；切回仍为默认值。已有合法编辑丢失，且没有撤销。另测 B.R0=92 也会丢失。

建议：保留共同有效且合法的时间；仅转换不兼容字段，并为需要初始化的场景保留可恢复的原值。

### P2：“适配”只重置缩放，不能适配完整时序

位置：`src/views/Mio16TimingView/components/TimingPreview.vue:20`、`:49`。

适配按钮只执行 setZoom(1)，但基础宽度由 `120 + periods * 240` 等下限决定。多周期的完整图仍超出视口，不能通过按钮看全。

复现：Periods=3，点放大后点适配，显示 1×；画布宽 840 px，而当前视口只有 515 px，仍需横向滚动。增加 Periods 会进一步扩大差距。

建议：适配按实际视口计算宽度/比例尺并定位起点；如仅想恢复默认缩放，应改名为“重置缩放”，避免承诺不存在的功能。
